# 身份文档规范

本文定义 Wallet Identity 的 DID Document、controller、公钥用途和版本更新规则。

## 核心规则

- DID 是钱包身份的稳定主键，文档 `id` 必须与 DID 一致。
- controller 是身份控制密钥；authentication、assertionMethod 和 recovery 使用明确的公钥用途。
- 文档更新必须递增 `revision`，签名覆盖规范化后的完整文档。
- 文档冲突时拒绝回退版本，不接受未授权 controller 的更新。
- 钱包地址、用户名、邮箱和 Passkey 都是身份关联对象，不是身份主键。

## 固定常量

```text
DID_METHOD                = did:yeying
IDENTITY_ID_PREFIX        = wid_
IDENTITY_ID_RANDOM_BITS   = 128 minimum
IDENTITY_DOCUMENT_VERSION = 1
SIGNATURE_ALGORITHM       = Ed25519 / EdDSA
CANONICALIZATION          = RFC 8785 JCS
```

时间使用 RFC 3339 UTC；随机数使用密码学安全随机源。私密材料永远不进入公开身份文档。

## 文档结构

```ts
type WalletIdentityDocument = {
  version: 1;
  id: `did:yeying:${string}`;
  createdAt: string;
  updatedAt: string;
  revision: number;
  controllers: IdentityController[];
  accounts: LinkedAccount[];
  issuers: TrustedIssuerLink[];
  recovery: RecoveryPolicy;
  proof?: IdentityDocumentProof;
};
```

控制器和账户关联对象：

```ts
type IdentityController = {
  controllerId: string;
  kind: 'wallet_key' | 'passkey' | 'mpc' | 'recovery_key';
  publicKey: string;
  algorithm: 'secp256k1' | 'ed25519' | 'p256' | 'multisig';
  purposes: Array<'authentication' | 'assertion' | 'manage' | 'recovery'>;
  status: 'active' | 'revoked';
  addedAt?: string;
  revokedAt?: string;
};

type LinkedAccount = {
  accountId: string;
  chainKey: string;
  family: 'evm' | 'utxo' | 'solana' | 'cosmos' | 'substrate' | 'sui';
  address: string;
  publicKey?: string;
  controllerId?: string;
  proof?: AccountLinkProof;
  status: 'active' | 'revoked';
  createdAt?: string;
  revokedAt?: string;
};
```

受信任 issuer 和恢复策略属于公开元数据，不能包含私钥：

```ts
type TrustedIssuerLink = {
  issuer: string;
  name?: string;
  credentialTypes: string[];
  jwksUri: string;
  status: 'active' | 'revoked';
};

type RecoveryPolicy = {
  controllers: string[];
  threshold: number;
  delaySeconds?: number;
};
```

控制器类型包括 `wallet_key`、`passkey`、`mpc` 和 `recovery_key`；用途必须明确区分 `authentication`、`assertion`、`manage`、`recovery`。账户关联记录至少包含 `accountId`、完整 `chainKey`、地址、公钥、controller、proof 和状态。

文档只保存 DID、控制器公钥和用途、关联地址、issuer 元数据及撤销信息，不保存助记词、私钥、TOTP secret 或其他私密材料。

账户关联 proof 必须绑定完整 DID、chain、address、用途、一次性 nonce 和有效期，并同时证明身份 controller 同意及新账户控制者拥有该地址：

```ts
type AccountLinkProof = {
  version: 1;
  purpose: 'identity-account-link';
  identity: string;
  account: { chainKey: string; address: string; publicKey?: string };
  nonce: string;
  issuedAt: string;
  expiresAt: string;
  identityControllerProof: SignatureProof;
  accountControlProof: SignatureProof;
};
```

EVM 使用 EIP-191，其他链使用对应原生签名域。

## 文档签名

签名输入固定为 `JCS(documentWithoutProof)` 的 UTF-8 字节。验证方必须检查 DID、verification method、controller 状态和用途、revision、签名及时间窗口。文档更新必须递增 revision，拒绝回退版本和未授权 controller 的更新。

## 多身份和多链

一个 DID 可以关联多个 EVM 或其他链账户，每条关联记录必须包含 chain、address、controller 和 account-link proof。不同 DID 始终独立，Wallet 不自动合并身份；地址变更不改变 DID。

## 验证

服务端必须校验 DID 格式、文档 id、revision、controller、公钥用途、签名和状态，再使用文档验证 Presentation 或凭证。

原身份模型中的 DID Document 字段和签名示例以本文为准。
