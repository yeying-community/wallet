# 通行证登录方案

> 状态：当前目标方案，尚未正式上线。
>
> 适用范围：Wallet、Node、web3-bs、Router 等 Web3 应用。

## 结论

“通行证登录”不再表示独立 Passport subject，也不再签发旧断言。它只是无钱包插件场景下的一种认证器入口：用户通过设备 Passkey 证明自己控制某个钱包身份，Node 再按授权码流程把钱包身份结果交给 Web3 应用。

正式身份主键只有：

```text
walletIdentityId = wid_<base64url-random>
did = did:yeying:<walletIdentityId>
```

钱包地址、用户名、邮箱、Passkey 都不是身份主键：

- 钱包地址是钱包身份已验证关联的链账户。
- 用户名是 `UsernameCredential`。
- 邮箱是 `EmailCredential`，需要邮箱验证码验证后由 Node 签发。
- Passkey 是认证器，用于无钱包插件登录和高风险确认。

## 有钱包插件登录

Web3 应用通过 web3-bs 请求 Wallet 出示钱包身份 presentation：

```text
yeying_identity_presentation
```

请求必须包含 `appId`、`audience`、`nonce`、scope 和过期时间。常用 scope：

```text
identity.basic
identity.wallet
identity.username
identity.email
```

Wallet 只出示用户已授权且本地持有的凭证。应用后端必须验证 presentation 的签名、holder、audience、nonce、scope 和有效期；需要邮箱或用户名时，还必须验证 JWT-VC issuer、JWKS、过期时间和 credential status。

## 钱包身份验证

Wallet 设置页负责帮助用户完成可复用的身份验证：

1. 创建或选择钱包身份文档。
2. 使用身份控制器签名身份文档。
3. 使用当前钱包账户签名 Node 生成的账户关联 challenge。
4. Node 验证账户关联 proof。
5. 用户填写用户名和邮箱。
6. Node 发送邮箱验证码并在确认后签发 `UsernameCredential` 和 `EmailCredential`。
7. Wallet 加密保存凭证到当前钱包身份。
8. 支持 WebAuthn 的环境中，Wallet 使用已签名身份文档向 Node 注册身份级 Passkey。

旧的“绑定通行证”不是新协议概念。界面可以使用“通行证登录”帮助用户理解无插件入口，但数据模型必须表达为钱包身份验证和认证器注册。

## 无钱包插件登录

应用后端创建 Node 身份授权请求：

```text
POST /api/v1/public/identity/authorize/request
```

Node 返回 `requestId` 和 `verifyUrl`。用户打开 `verifyUrl` 后使用设备 Passkey 确认：

```text
POST /api/v1/public/identity/authorize/challenge
POST /api/v1/public/identity/authorize/approve
```

应用后端随后用 PKCE verifier 换码：

```text
POST /api/v1/public/identity/authorize/exchange
```

exchange 结果包含：

- `did`
- `walletIdentityId`
- `walletAddress`
- `scopes`
- `credentials[]`

结果不包含 `subjectId`，也不需要旧断言。

## 与 Router 的关系

Router 明确需要 `identity.email`。如果 Wallet 没有 `EmailCredential`，Router 应提示用户先在夜莺钱包插件中完成钱包身份验证和邮箱验证。无钱包插件时，Node 的 Passkey 授权也必须检查请求 scope：缺少邮箱凭证时拒绝授权。

## 移除项

新实现不再保留以下兼容逻辑：

- `yeying_passport_assertion`
- Wallet 本地旧凭证类型 `email` / `username` 到正式类型的兼容映射
- 旧断言签发与 introspection
- `subjectId` / `sub_xxx` 作为外部身份主键
- Web3 应用侧 Passport binding 表
