# 身份凭证规范

本文定义身份 issuer、JWKS、JWT-VC 和凭证状态。

## Issuer 元数据

```json
{
  "issuer": "did:web:node.example",
  "credentialTypes": ["UsernameCredential", "EmailCredential", "AvatarCredential"],
  "jwksUri": "https://node.example/.well-known/jwks.json",
  "credentialStatusBatchUri": "/api/v1/public/identity/credentials/status"
}
```

Wallet 和 DApp 必须固定信任 issuer，不能因为 JWT 的 `iss` 自己声明就自动信任。

## 凭证类型

- `UsernameCredential`：已验证用户名。
- `EmailCredential`：已验证邮箱。
- `AvatarCredential`：已验证头像 URI。

所有凭证的 `subject` 必须是钱包身份 DID，不能使用地址、邮箱或用户名作为长期主键。凭证必须包含可信 issuer、签名、`nbf`、`exp` 和唯一 `jti`。

## JWKS 和 JWT-VC

- JWK 使用 `kty=OKP`、`crv=Ed25519`、`alg=EdDSA`，每个 key 有唯一 `kid`。
- JWT-VC 使用 compact JWS；`vc.type` 必须包含 `VerifiableCredential` 和具体凭证类型。
- `EmailCredential`、`UsernameCredential`、`AvatarCredential` 的 `credentialSubject.id` 必须等于 `sub`。
- issuer 轮换时保留旧 key 至其签发凭证全部过期，并在撤销窗口后移除。

```json
{
  "iss": "did:web:node.example",
  "sub": "did:yeying:wid_example",
  "jti": "urn:credential:email-01",
  "nbf": 1786579200,
  "exp": 1786665600,
  "vc": {
    "type": ["VerifiableCredential", "EmailCredential"],
    "credentialSubject": {
      "id": "did:yeying:wid_example",
      "email": "person@example.com",
      "emailVerifiedAt": "2026-08-13T00:00:00Z"
    }
  }
}
```

## 验证和状态

服务端按 issuer、JWKS、签名、subject、类型、有效期和状态顺序验证。状态至少区分 `active`、`revoked`、`superseded`、`expired` 和 `unknown`；未知状态必须拒绝高风险操作。

JWT-VC 必须使用 Ed25519 `EdDSA`，JWT header 包含受信 `kid`。`EmailCredential`、`UsernameCredential` 和 `AvatarCredential` 默认短期有效；Wallet 不得出示过期、尚未生效或临近过期凭证。凭证续签必须绑定 DID、credential type、一次性 challenge 和 controller proof，不能只凭 DID 重签。

高风险流程的凭证状态缓存最多 5 分钟；低风险只读展示最多 1 小时。状态查询失败不得转化为 `active`。

凭证到期不代表已验证事实失效。允许续签时，续签请求必须绑定 DID、凭证类型、一次性 challenge 和 controller proof；源事实不存在、已撤销或 proof 无效时不得续签过期凭证。
