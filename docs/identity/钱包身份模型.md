# 钱包身份模型

> 状态：当前身份模型基线。

本文只定义 Wallet Identity 的核心对象、关联关系、生命周期和安全不变量。跨系统组件关系和信任边界见[钱包身份架构](../architecture/钱包身份.md)；协议调用、认证器实现、应用接入和测试分别由关联文档维护。

## 1. 核心结论

钱包身份是跨 Wallet、Node 和 Web3 应用使用的稳定身份主体。身份主键由用户侧钱包客户端本地生成；通常由 Wallet 插件生成，没有插件时也可由 Node Web 的临时 Wallet Bootstrap 客户端生成：

```text
did:yeying:wid_<base64url-random>
```

DID 不由钱包地址、邮箱、用户名、助记词或 Node 数据库 ID 派生。Wallet 插件与 Node Web Bootstrap 必须使用兼容的 DID Document、controller/recovery、账户证明和 custody v2 格式；身份密钥始终由用户侧客户端控制，Node 服务和应用只能验证和引用该 DID。

## 2. 对象关系

| 对象 | 主键或形式 | 所有者 | 模型职责 |
| --- | --- | --- | --- |
| 钱包身份 | `did:yeying:wid_*` | 用户 | 跨设备、跨应用的长期身份主体 |
| 身份控制器 | 公钥、钱包密钥、Passkey、MPC 或恢复密钥 | 用户 | 控制身份文档、签名和恢复操作 |
| 链账户 | `chainKey + address` | 用户 | 可关联或移除的链账户，不等于身份 |
| 账户关联证明 | 身份 controller proof + 账户控制 proof | 用户 | 证明链账户属于某个 DID |
| Issuer | `did:web:*` 或受信 HTTPS issuer | 验证服务 | 签发、更新和撤销资料凭证 |
| 身份凭证 | compact JWS JWT-VC | 用户持有，issuer 可撤销 | 按 scope 出示已验证资料 |
| 身份认证器 | Passkey、TOTP 等 | 用户设备或认证服务 | 证明用户控制认证器 |
| DApp 用户 | DApp 自有 `localUserId` | DApp | 保存业务会话和业务权限 |

```text
Wallet Identity DID
    ├── controller / recovery controller
    ├── 一个或多个链账户关联证明
    ├── UsernameCredential
    ├── EmailCredential
    ├── AvatarCredential
    └── Passkey / TOTP 认证器
```

对象关系图：

```plantuml
@startuml wallet-identity-core
left to right direction
actor User
component "Wallet Identity\nDID" as Identity
component "Controllers\nwallet / recovery / passkey / MPC" as Controllers
component "Linked Accounts\nEVM / other chains" as Accounts
component "Issuer" as Issuer
component "Credentials\nusername / email / avatar" as Credentials
component "Authenticators\npasskey / TOTP" as Auth
component "DApp" as App

User --> Identity : owns
Controllers --> Identity : controls
Accounts --> Identity : linked by proof
Issuer --> Credentials : signs / revokes
Credentials --> Identity : subject = DID
Auth --> Identity : authenticates
Identity --> App : scoped identity result
App --> App : local session and permissions
@enduml
```

- 钱包地址是经过验证的关联账户，不是身份主键。
- 用户名、邮箱和头像是 issuer 签发的可验证凭证，不是身份主键。
- Passkey 和 TOTP 是身份认证器，不是独立身份主体。
- 一个 DID 可以关联多个地址、多个凭证和多个认证器。
- 同一个 active `chainKey + address` 只能关联一个 DID；第二个 DID 使用同一地址验证必须失败。
- 不同 DID 必须保持独立，Wallet 不自动合并身份。

## 3. 身份文档和控制器

身份 DID Document 声明 DID、controller、公钥用途和 revision。controller 负责身份文档更新、Presentation 签名和恢复授权。文档签名、版本冲突和公钥用途见[身份文档规范](./身份文档规范.md)。

## 4. 地址和凭证关联

地址关联必须包含链标识、地址、DID、一次性 nonce 和可验证 proof。地址变更不改变 DID，也不使其他凭证失效。凭证 subject 必须是 DID，issuer、签名、有效期和撤销状态必须可验证，详见[身份凭证规范](./身份凭证规范.md)。

### 链账户关联

`chainKey` 是完整命名空间，不得只使用数字 chain ID，推荐使用 CAIP-2 或等价形式，例如 `eip155:1`。将账户加入身份必须同时证明身份 controller 同意和新账户控制者拥有该地址。关联 proof 必须绑定 DID、chain、address、用途、一次性 nonce 和有效期。EVM 使用 EIP-191，其他链使用对应原生签名域。同一 active 地址已经归属其他 DID 时，issuer 必须返回确定错误，不能自动合并或覆盖。

当前 Node 账户关联接口为：

```text
POST /api/v1/public/identity/account-links/challenge
POST /api/v1/public/identity/account-links/verify
```

当前实现支持 EVM `eip155:<chainId>`；其他链必须使用独立适配器，不能复用 EIP-191。

## 5. 认证器定位

认证器用于证明用户控制某个身份认证设备：

- 通行密钥（Passkey）基于 Web 身份验证（Web Authentication，简称 WebAuthn），支持无 Wallet 插件身份登录，并可作为指定托管流程的认证门槛；身份管理敏感操作由 DID controller 授权。术语和凭证边界见[身份认证器](./身份认证器.md)。
- Wallet 插件创建身份时 Passkey 可以事后注册；Node Web 邮箱 Bootstrap 因为需要建立无插件登录与云端恢复能力，激活身份前必须完成 Passkey，不能用邮箱 OTP 代替。
- TOTP 用于敏感操作的二次确认。
- 认证器绑定 DID，不绑定单个钱包地址。
- 认证器注册、验证、撤销和 RP/origin 规则见[身份认证器](./身份认证器.md)。

## 6. 身份生命周期

身份生命周期包含创建、验证、使用、变更和恢复。Wallet 插件路径从已有身份控制密钥开始；没有插件时，Node Web Bootstrap 在浏览器本地创建兼容的 DID 和密钥材料，并要求注册通行密钥后才能完成激活。两条路径共享 DID、账户关联和身份凭证模型：

```plantuml
@startuml wallet-identity-lifecycle
autonumber
actor "用户" as User
participant "Wallet 插件 / Node Web Bootstrap" as Client
participant "认证器" as Authenticator
participant "Node 身份服务" as Node
participant "DApp" as App

== 创建身份 ==
User -> Client : 创建或选择钱包身份
alt 使用 Wallet 插件
  Client -> Client : 本地生成 DID、controller/recovery 密钥
  Client -> Client : 用钱包密码加密并保存身份密钥材料
else 无 Wallet 插件，使用 Node Web Bootstrap
  Client -> Client : 本地生成兼容 DID、controller/recovery 密钥和钱包账户
  Client -> Node : 请求邮箱验证码并提交验证
  Node --> User : 发送邮箱 OTP
  User -> Client : 输入邮箱 OTP
  Client -> Node : 确认 OTP并请求初始通行密钥登记
  Node --> Client : 返回 WebAuthn 创建 challenge
  Client -> Authenticator : 创建通行密钥（Passkey）
  User -> Authenticator : 完成设备用户验证
  Authenticator --> Client : 返回注册凭证
  Client -> Node : 提交凭证和 DID Document
  Node -> Node : 验证 challenge、origin、RP ID和凭证
  Node --> Client : 登记成功
end

== 关联账户与验证资料 ==
Client -> Node : 请求链账户关联 challenge
Node --> Client : 返回绑定 DID 和账户的 challenge
Client -> Client : 使用身份 controller 和链账户分别签名
Client -> Node : 提交身份证明、账户证明和 DID Document
Node -> Node : 验证签名、nonce、chainKey 和地址唯一性
Node --> Client : 账户关联结果

opt 验证邮箱、用户名或头像
  User -> Client : 提交资料并完成相应验证
  Client -> Node : 提交验证结果
  Node -> Node : 签发或更新 subject 为 DID 的资料凭证
  Node --> Client : 返回凭证及状态
end

opt 为已有 Wallet 身份添加通行密钥
  User -> Client : 请求添加通行密钥
  Client -> Client : controller 签署本次敏感操作授权
  Client -> Node : 请求通行密钥注册 challenge 和授权
  Node --> Client : 返回 WebAuthn 创建 challenge
  Client -> Authenticator : 创建通行密钥（Passkey）
  User -> Authenticator : 完成设备用户验证
  Authenticator --> Client : 返回注册凭证
  Client -> Node : 提交凭证和操作授权
  Node -> Node : 验证 challenge、origin、RP ID和授权
  Node --> Client : 通行密钥绑定到原 DID
end

== 向应用出示身份 ==
App -> Node : 创建应用身份授权请求
Node --> App : 返回 requestId 和授权页面
alt 使用 Wallet 插件
  App -> Client : 请求 Wallet 身份授权
  Client -> Client : 用户确认 scope，controller 签名 Presentation
  Client --> App : 返回绑定 audience、nonce、scope 的 Presentation
  App -> App : 验证 Presentation 并建立应用会话
else 无 Wallet 插件，使用通行密钥
  User -> Node : 在 Node 授权页确认应用和资料范围
  Node --> Client : 返回 WebAuthn 认证 challenge
  Client -> Authenticator : 使用已登记通行密钥认证
  User -> Authenticator : 完成设备用户验证
  Authenticator --> Client : 返回 assertion
  Client -> Node : 提交 assertion 和授权请求
  Node -> Node : 验证凭证、challenge、origin、RP ID和 scope
  Node --> App : 返回一次性授权码
  App -> Node : 使用 PKCE verifier 兑换授权码
  Node --> App : 返回 DID 和获准的资料
  App -> App : 建立自己的应用会话
end

== 更新、撤销与恢复 ==
opt 更新身份或资料
  User -> Client : 请求变更身份或验证资料
  Client -> Client : controller 授权身份变更
  Client -> Node : 提交更新后的 DID Document 或资料验证
  Node -> Node : 校验 revision、签名和凭证策略
  Node --> Client : 返回更新结果
end

opt 撤销认证器
  User -> Client : 选择撤销某条认证器
  Client -> Client : controller 签署撤销操作授权
  Client -> Node : 提交撤销请求和操作授权
  Node -> Node : 将认证器标记为 revoked
  Node --> Client : 返回撤销结果
end

opt 从云端密钥托管恢复
  User -> Client : 发起钱包恢复并验证通行密钥
  Client -> Node : 请求 custody.recovery 授权
  Node --> Client : 返回短期读取授权
  Client -> Node : 读取钱包加密密文
  Node --> Client : 返回密文
  User -> Client : 输入创建托管记录时的钱包密码
  Client -> Client : 本地解密并校验身份密钥、DID和账户
  Client --> User : 恢复原 DID 和钱包控制权
end
@enduml
```

图中的两种应用登录方式不能互换：Wallet 插件通过 DID controller 签署 Presentation；无插件流程由 Node 验证 Passkey assertion 并签发授权码。Passkey 本身只证明认证器控制权，不能恢复身份私钥。身份恢复依赖 recovery controller 或明确的恢复材料。Wallet 当前将 controller 私钥和 recovery 私钥保存在本地身份记录的 `encryptedKeyMaterial` 中。WebDAV 普通数据备份和 Passkey 应用登录本身不会恢复这些私钥；Wallet v2 密钥托管 payload 则会把 `identities`、`selectedIdentityId` 和每个身份的 `encryptedKeyMaterial` 一并放入用户密码加密的 `ciphertext`。取得 `custody.recovery` 短期授权后，Wallet 在本地用原密码解密并校验材料，从而恢复同一个 DID、controller/recovery 和链账户地址。Node 只能返回密文，不能恢复或读取私钥。丢失日常钱包地址不应删除 DID；恢复 controller 后可以重新建立地址关联。生命周期细节见[身份生命周期](./身份生命周期.md)。

## 7. 安全不变量

1. DID 是唯一跨系统身份主键。
2. 地址、邮箱、用户名和认证器不能单独替代 DID。
3. 凭证必须绑定 DID，并验证 issuer、签名、有效期和状态。
4. Presentation 必须绑定 audience、nonce、scope 和有效期。
5. Wallet、Node、DApp 各自验证自己负责的边界，不共享私钥或长期秘密。
6. 恢复和撤销不能通过单个普通地址绕过 controller 安全策略。
