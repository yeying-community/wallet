# 钱包登录验收标准

> 本文按协议定义可重复执行的浏览器验收。页面名称以 Wallet 当前 UI 为准，协议语义以 `docs/协议规范/` 为准。

## 1. 验收总则

- 每次测试记录 DApp origin、请求方法、账户、钱包锁定状态、已授权状态和最终错误码。
- 用户拒绝必须结束当前请求，不能自动重试或返回部分成功结果。
- Wallet 不向 DApp 暴露助记词、私钥、钱包密码或内部存储对象。
- 已有权限只能减少重复的连接确认，不能复用旧 SIWE nonce、旧签名或旧身份出示证明。

## 2. 页面与交互计数

| 场景 | 页面顺序 | 用户确认次数 |
| --- | --- | --- |
| 已解锁账户连接 | 连接请求 | 1 |
| 锁定状态账户连接 | 解锁钱包 -> 连接请求 | 2 |
| 首次 SIWE 登录 | 解锁（需要时）-> 连接请求（需要时）-> SIWE 签名请求 | 2 或 3 |
| 已连接账户的 SIWE 登录 | SIWE 签名请求 | 1 |
| 首次钱包身份登录 | 解锁（需要时）-> 连接请求 | 1 或 2 |
| 已授权 scope 的钱包身份登录 | 解锁（需要时）-> 直接返回 Presentation | 0 或 1 |
| 钱包身份 + SIWE 组合 | 钱包身份 scope 授权（需要时）-> SIWE 签名请求 | 1 至 3 |
| Passkey 无插件登录 | 系统 Passkey 验证界面 -> 应用回调 | 1 次系统验证 |
| UCAN 能力授权 | 钱包授权/签名请求 | 1 |

解锁页面只展示解锁原因和密码输入；连接页面展示网站 origin、请求账户及身份资料 scope；签名页面展示待签名的完整消息或结构化摘要。

## 3. EIP-1193 账户连接

### 请求

DApp 调用 `eth_requestAccounts`。只需要账户时，不得要求 SIWE 签名、身份资料或 UCAN。

### 页面

连接请求页面必须显示：网站 origin、请求的账户能力，以及“连接/拒绝”按钮。若同时调用 `wallet_requestPermissions`，必须在同一页面明确列出账户能力和各项 `wallet_identity.scopes`，不能隐藏身份资料权限。

### 成功与失败

允许后返回账户地址和权限结果；拒绝返回 `USER_REJECTED`。锁定时先完成一次解锁，错误密码不得进入连接授权页。撤销站点授权后再次请求必须重新显示连接页。

## 4. 纯 SIWE 登录

### 请求

应用后端生成一次性 SIWE challenge，包含 domain、address、statement、URI、version、chain-id、nonce、issued-at 和 expiration-time。DApp 调用 `personal_sign` 或标准 SIWE 签名入口。

### 页面

签名请求页显示：登录网站、签名地址、SIWE statement、URI、网络、nonce、签发时间和过期时间。纯 SIWE 请求只进入签名审批流程，不请求身份 scope，也不生成 `wallet_identity_presentation`。

### 成功与失败

用户确认一次后返回签名。服务端验证 EIP-4361 字段、nonce、时间窗口和签名地址。重复 nonce、domain 不匹配、过期或地址不匹配必须拒绝，Wallet 和服务端均不得将旧签名当作新登录。

## 5. 钱包身份登录授权

### 请求

应用通过 web3-bs 或自有后端创建一次性 identity login session，再通过 `wallet_requestPermissions` 请求固定的 `wallet_identity.scopes`。本流程不要求先执行 SIWE。

### 页面顺序

1. 解锁钱包：仅在 Wallet 锁定时出现。
2. 连接请求：仅在本次请求包含未授权 scope 时出现；同一页显示 origin 和用户名、邮箱、头像等具体 scope。未请求的资料不得展示为已授权。
3. 身份出示：scope 已授权后，Wallet 直接生成绑定 audience、nonce、scope 和有效期的 Presentation。
4. SIWE 签名请求：仅在业务另外调用 SIWE 时出现，不属于钱包身份协议的固定步骤。

### 交互与结果

新增资料 scope 需要一次明确确认；已授权 scope 不重复确认。成功结果包含签名的 `wallet_identity_presentation`；服务端独立验证 DID 签名、audience、nonce、scope、issuer、subject 和有效期。缺少已验证凭证、scope 不足、nonce 重放或用户拒绝必须返回确定错误。

## 6. Passkey 无插件登录

应用向身份服务发起 Passkey challenge，浏览器显示系统 WebAuthn 验证界面。该流程不调用 Wallet Provider 的账户连接、SIWE 签名或身份 scope 授权。验证成功后服务端签发应用会话或 authorization code；失败、取消、origin/RP ID 不匹配和已撤销凭证必须拒绝。

## 7. UCAN 能力授权

UCAN 不是登录协议。应用完成账户登录后，针对具体 audience、resource、capability 和有效期单独请求授权。Wallet 授权页必须显示服务、资源、动作、有效期和签名主体；用户确认一次后返回 UCAN 或授权签名。Node 登录会话不能直接充当 Router、Warehouse 或 WebDAV 的资源令牌。

## 8. 已授权与再次登录

- 已连接站点再次调用 `eth_requestAccounts` 可直接返回已批准账户，但站点撤销后必须重新确认。
- 再次 SIWE 必须使用新 nonce 和新签名。
- 再次身份登录必须生成新的 audience、nonce 和身份出示证明。
- 登出只清理 DApp 会话和本地缓存，不删除钱包、身份、凭证或站点授权；下一次请求是否显示连接页由授权状态决定。

## 9. 错误验收矩阵

| 条件 | 预期结果 |
| --- | --- |
| 用户拒绝任一页面 | `USER_REJECTED`，请求终止 |
| Wallet 锁定且密码错误 | `WALLET_LOCKED` 或确定解锁错误，不显示成功 |
| 未请求身份 scope | 连接页不显示身份资料权限，不返回身份资料 |
| scope 缺少对应凭证 | 身份登录拒绝并返回凭证缺失错误 |
| SIWE nonce 重放 | 服务端拒绝 |
| Presentation audience/nonce 不匹配 | 服务端拒绝 |
| Presentation 过期或 issuer 未信任 | 服务端拒绝 |
| UCAN audience 或 capability 不匹配 | 资源服务拒绝 |

## 10. 最小回归用例

1. 清空站点授权，分别验证账户连接、纯 SIWE、钱包身份、钱包身份与 SIWE 组合、Passkey 和 UCAN。
2. 对每个场景重复执行“允许、拒绝、锁定、错误密码、刷新页面、重新登录”。
3. 检查页面字段与请求 scope 一致，确认未请求的资料不会出现。
4. 抓取最终 RPC 响应和服务端验证结果，确认 nonce、audience、scope、签名地址和凭证有效期均被校验。
5. 登出后重新登录，确认旧会话、旧 nonce 和旧 Presentation 均不能复用。
